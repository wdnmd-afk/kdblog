kdblog 界面规格

一个单人维护的内容发布系统。功能已实现并跑通，本文列出每屏要承载什么、有哪些操作、 以及容易被漏掉的状态，供出设计稿使用。

11 个界面 前台 2 · 后台 9 21 个写操作 单管理员，无多角色

这个系统在做什么

写文章、发布、给搜索引擎看。四个内容模块（文章 / 页面 / 分类 / 标签）加一个回收站， 前台只对外暴露首页与文章详情两个页面。

三条硬约束会影响设计判断：

1. SEO 是发布的前置条件，不是可选项。SEO 标题、描述、关键词三项缺一就不能发布—— 这个拦截时刻需要设计得清楚，用户会撞上它。

2. 只有一个管理员账号。没有成员管理、没有权限分级、没有协作冲突， 不必设计头像组或"谁在编辑"。

3. 页面（Page）只存不显。后台能建能编，但前台当前不渲染它们， 列表里需要说明这一点，否则用户会疑惑建完的页面去哪了。

前台

读者能看到的全部。设计重点是长文可读性，不是功能密度。

首页

/
目的
让读者找到文章。唯一入口，没有导航菜单、没有搜索、没有分页。
数据
站名、已发布文章列表（发布日期 · 分类 / 标题 / 摘要），最多 20 条，按发布时间倒序。
操作
点标题进文章；角落一个进后台的入口。
状态
无文章：引导去写第一篇 摘要为空（可省略） 文章无分类 超长标题换行

文章详情

/posts/{slug}-{id}
目的
阅读。这是全站唯一被搜索引擎收录的内容页，排版质量直接影响停留时间。
数据
标题、发布日期、分类、标签、正文富文本、返回首页。
正文元素
二/三/四级标题、段落、加粗、斜体、下划线、删除线、行内代码、代码块、 引用、有序/无序列表、分割线、图片、表格、链接（外链自动带 nofollow）。 这 14 种元素都需要给出排版样式，正文由编辑器产出，用户会用到全部。
操作
返回首页。无评论、无点赞、无分享按钮、无目录导航。
状态
预览模式：吸顶横幅，说明"未发布、不被收录" 无分类 / 无标签 无发布日期（草稿预览时） 超长代码块横向滚动

后台

桌面优先，侧栏固定 6 项导航（仪表盘 / 文章 / 分类 / 标签 / 回收站 / 系统日志）+ 底部账号区与退出。 不需要移动端适配，但不应横向溢出。

2026-09-24 更新：独立页面（Page）模块已整体移除（不产出前台路由，无实际作用）， 侧栏不再有「页面」一项，仪表盘 KPI 由四张改为三张，回收站只处理文章。

登录

/login
数据
账号、密码两个字段。账号不是邮箱，是任意用户名（当前是 admin），不要设计成邮箱输入。
操作
登录。无注册、无找回密码、无第三方登录、无"记住我"。
状态
凭据错误："账号或密码不正确" 提交中 已登录访问时直接跳转后台

仪表盘

/admin
数据
六个计数：已发布文章、草稿、页面、分类、标签、回收站。每个可点击进对应列表（前两个带状态筛选）。
操作
"写文章"主按钮。
状态
全部为 0（新装系统）
说明
没有趋势图、没有访问统计、没有最近活动流——数据层没有这些。 如果设计稿加了图表，需要先加埋点与统计表。

文章列表

/admin/posts
数据
表格六列：标题、分类、状态、SEO、更新时间、操作。每页 20 条。
SEO 列
显示关键词数量或"未填"。这列是发布质量的信号——未填意味着这篇发不出去， 值得设计成能一眼扫到的形式。
筛选
状态切换（全部 / 已发布 / 草稿）+ 标题/slug 关键词搜索。筛选走 URL 参数，可分享链接。
操作
点标题进编辑；已发布的有"查看"外链；行内操作：取消发布、移入回收站。顶部"写文章"。
状态
无文章：引导写第一篇 筛选无结果（与"无文章"文案要区分） 操作进行中 单页内（不显示分页）

文章编辑

/admin/posts/{id} · /new
目的
整个系统最重要的一屏，用户 90% 的时间在这里。新建与编辑同一个界面。
常驻区
标题输入（大字号，无边框感）+ 右上三个动作：预览、保存草稿、发布。
四个 Tab
  • 内容——富文本编辑器 + 工具栏
  • 设置——URL slug、摘要、分类下拉、标签（勾选既有 + 输入新建）
  • SEO——见下方字段表，带实时字数条与关键词命中提示
  • 版本——快照列表（版本号 · 标题 · 时间 + 回滚），保留最近 20 版
状态
发布被拦：SEO 不合规，自动切到 SEO Tab 并标红字段 slug 已被占用 保存中 / 发布中 已保存 / 已发布提示 图片上传中 / 上传失败 新建时无版本记录 预览链接已生成（30 分钟有效，需可复制）

页面列表 / 页面编辑（已移除）

/admin/pages · /admin/pages/{id} · 2026-09-24 随模块删除
移除说明
该模块不产出前台路由，仅作内容存储，已连同数据库表一并删除。下方描述保留作历史记录，不再对应当前实现。
数据
列表四列：标题、路径、状态、更新时间 + 操作。编辑只有标题、slug、摘要、正文——没有 SEO Tab、没有分类标签、没有版本历史。
操作
列表行内可直接发布/取消发布/删除（页面无 SEO 校验，不必进编辑器）。
状态
无页面 slug 撞系统保留字（posts/admin/api 等） 提示"前台暂不渲染"

分类管理

/admin/categories
数据
树形结构（父子层级，用缩进表达）+ 每个分类的文章数。字段：名称、slug、描述、父分类。
布局
当前是左树右表单。表单在新建与编辑间切换，编辑时需明确"正在编辑哪一个"。
操作
新建、编辑、删除。删除有文章的分类会把文章置为未分类，需要在确认时说明。
状态
无分类 该分类下有子分类，不能删 不能把分类移到自己的子分类下 多层嵌套（深度无限制，需考虑缩进上限）

标签管理

/admin/tags
数据
扁平列表（无层级）+ 每个标签的文章数。字段只有名称与 slug，slug 可留空自动生成。
操作
新建、编辑、删除。删除只解除文章关联，不影响文章本身——确认文案可以比分类温和。
状态
无标签（提示写文章时也能顺手创建） 标签名重复 标签数量很多时的排布

回收站

/admin/trash
数据
文章与页面混在一张表：类型、标题、路径、删除时间。按删除时间倒序。
操作
还原、彻底删除。彻底删除不可恢复，走行内二次确认（当前是就地替换成"确认 / 取消"）。
状态
回收站为空 等待二次确认 操作进行中

SEO 字段与校验

发布前会强校验前三项。字数按中英混排计宽（中文字符算 2）， 设计时需要给出进度条的正常 / 接近上限 / 超限三种表现。

字段 限制 发布必填 设计要点
SEO 标题 10–60 字符
中文建议 ≤ 30 字		 必填 实时字数条；未含主关键词时提示
SEO 描述 40–160 字符
中文建议 60–80 字		 必填 同上，多行输入
关键词 3–8 个 必填 标签式输入，第一个是主关键词需要视觉区分；可删除、自动去重
URL slug ≤ 80 字符 必填 仅小写字母数字连字符；需实时展示最终地址 /posts/{slug}-{id}
Canonical URL 完整 URL 选填 留空自动生成，需说明"仅跨站同发时才填"
og 图片 1200 × 630
≤ 200 KB		 选填 缺省回退：正文首图 → 站点默认图。当前只能填路径，没有上传与预览
robots 4 个枚举值 有默认值 下拉选择，非自由输入：index,follow 等四种组合

发布拦截是必须设计的时刻。用户在"内容"Tab 写完点发布， 若 SEO 三项没填会被拒绝并跳到 SEO Tab。这个跳转如果没有解释， 用户会以为是 bug。需要一条清楚的说明加字段级标红。

编辑器工具栏

15 个操作，按语义分四组。每个都需要图标 + 激活态（光标落在该格式内时按钮亮起）。

标题

二级标题 三级标题 四级标题

行内格式

加粗 斜体 下划线 删除线 行内代码

块级

无序列表 有序列表 引用 代码块 分割线

插入

链接 图片

一级标题刻意不提供——文章标题本身就是页面唯一的 h1，正文再出现会影响 SEO。

图片上传：≤ 10 MB，支持 JPEG / PNG / WebP / GIF， 上传后自动转 WebP 并生成 480 / 960 / 1440 三档。上传中需要有进度或忙态。

状态清单

最容易在设计稿里被漏掉的部分。下面是系统实际会返回的提示，文案已定，需要给出承载形式。

类型 出现时机 实际文案
阻塞 slug 重复 该 slug 已被占用，请更换
阻塞 页面 slug 撞保留字 该 slug 为系统保留字，请更换
阻塞 删除有子分类的分类 该分类下还有子分类，请先处理子分类
阻塞 分类移到自己子级下 不能把分类移动到自己的子分类下
阻塞 标签名重复 该标签名已存在
会话 登录过期后操作 登录状态已失效，请重新登录
失效 操作已删除的内容 文章不存在或已被删除
兜底 未预期错误 操作失败，请稍后重试

此外每屏都需要：空状态（带明确的下一步动作，而非只说"暂无数据"）、 操作进行中（按钮忙态 + 禁用）、成功反馈（已保存 / 已发布）。 内容状态共四种枚举：草稿、已发布、定时发布、已归档——后两种数据层预留但当前不产生， 设计上可以只处理前两种。

需要你定的事

这几处当前实现做了取舍，重新设计时值得重新判断。

01

og 图片没有上传入口

现在只能手填路径，而上传接口是现成的。如果设计里加上传 + 1200×630 裁剪预览， 实现成本不高，但会多一块界面。

02

媒体库没有界面

图片能上传、能在正文里用，但没有统一的媒体管理页——传过的图无法浏览、复用或删除。 要不要补这一屏是个明确的范围决定。

03

版本历史只能回滚，不能对比

列表给出版本号与时间，回滚是整篇覆盖。若要 diff 视图，需要设计双栏对比或行内高亮。

04

前台没有分类页、标签页、归档页

分类和标签当前只是后台的组织维度，读者点不进去。补这些页面要同时加前台路由， 但服务层查询已具备。

05

页面（Page）建了但前台不显示

"关于""联系"这类静态页存在数据里但访问不到。要么补前台渲染， 要么在后台明确标注它们的用途，避免用户困惑。

06

后台是桌面单栏布局

侧栏固定 224px，内容区最大 1152px。若要移动端可用（手机上改文章）， 侧栏需要抽屉化，编辑器的四 Tab 也要重新排布。

以上内容对应已实现并验证通过的功能。前台 2 屏 + 后台 9 屏，共 21 个写操作。 数据字段与校验规则以代码为准，设计稿如需改动字段范围，改动量不大但需同步后端。
