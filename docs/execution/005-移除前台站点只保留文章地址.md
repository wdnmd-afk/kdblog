# 移除前台站点，只保留文章地址

- 文档编号：005
- 状态：代码层已完成；未运行 typecheck / lint / build / test:http（按规则需先经用户同意）
- 创建日期：2026-09-23
- 适用范围：`app/(site)` 前台、根路径、后台页脚
- 前置文档：001（基础架构）、004（仪表盘重构）

## 一、目标

不再对外提供「站点」形态，只保留文章详情地址可被访问与分享：

1. 删除前台文章列表页（原 `/`）
2. 根路径 `/` 不再展示内容
3. 删除后台页脚的「访问站点」入口

## 二、已确认的决策（由用户选定）

| 决策项 | 结论 | 理由 |
| --- | --- | --- |
| 根路径 `/` 的行为 | **307 重定向到 `/admin`** | 前台已无内容可展示。重定向写在 `next.config.ts` 而非建一个只为跳转的页面组件——纯路由层配置，不必渲染 React |
| 重定向永久性 | `permanent: false`（307，非 308） | 308 会被浏览器与中间代理长期缓存。将来若要恢复前台首页，老用户仍会被弹进后台 |
| 站名页头与「返回首页」 | **全部删除** | 没有首页可回。保留这些链接会把读者送到 `/admin` → 登录页，对拿到文章/预览链接的访客是纯困惑 |
| 文章地址格式 | 不变，仍为 `/posts/{slug}-{id}` | 本次不动 URL 结构，已分享出去的文章链接全部继续有效 |
| 依赖变更 | 无 | 只删代码，不加依赖 |

### 保留不动

| 项 | 原因 |
| --- | --- |
| `/posts/{slug}-{id}` 路由 | 本次的目的就是保住它 |
| `(site)/layout.tsx` 的页脚版权 | 文章页仍需要一个页脚收尾 |
| `getPublishedPostCached` / `listPostsForSitemapCached` | 文章详情页与 sitemap 仍在用 |
| `robots.ts` 的 `allow: "/"` | 含义是「允许抓取全站」，不是「首页可抓」。`/` 本身是 307，爬虫跟随后会撞上 `disallow: /admin`，行为正确 |
| `lib/url.ts` 的 `getSiteUrl()` | `buildPostUrl()` 仍依赖它生成 canonical 与 sitemap 的绝对地址 |

## 四、潜在风险

| 风险 | 影响 | 处置 |
| --- | --- | --- |
| 搜索引擎已收录旧首页 | `/` 变 307 后，原首页的收录会被逐步替换为重定向目标；而目标 `/admin` 在 robots 里被 disallow，最终该 URL 会从索引中掉出 | 这与「不再对外提供站点」的目标一致，无需干预。文章页的收录不受影响（sitemap 仍在提交它们） |
| 读者书签指向旧首页 | 会被带到登录页 | 属预期行为。若希望改为 404，改 `next.config.ts` 一行即可 |
| `(site)` 分组只剩一个真实页面 | 目录看起来略空 | 刻意保留分组：`layout.tsx` 的页脚与「不引用后台入口」这条边界仍然有效，且将来单独部署前台时整体搬走即可 |
| 测试脚本的前台断言覆盖面变小 | 「前台不含后台链接」现在只测 `/preview-error` | 文章详情页的同类断言依赖库里存在已发布文章，当前脚本未做数据准备，故未纳入。已在第六节记为待办 |
