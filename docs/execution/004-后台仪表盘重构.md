- 适用范围：`/admin` 首页仪表盘

## 一、目标

把仪表盘从「6 张纯数字卡片」升级为可用的工作台，且**整页正好占满一屏、不出现整页滚动条**：

1. 关键指标（KPI）带趋势提示，能一眼看出内容是在增长还是停滞
2. 加入图表统计：发布趋势、分类分布
3. 把 SEO 缺失、回收站堆积、日志报错这类"需要处理的事"顶到首页
4. 卡片数量克制：每块都要回答一个 KPI 数字答不了的问题，否则不留

## 二、已确认的决策

| 决策项 | 结论 | 理由 |
| --- | --- | --- |
| 图表实现方式 | 手写 CSS 比例尺寸，**不引入图表库** | 全局规则禁止非必要依赖；recharts 约 100KB 且必须走客户端组件，而仪表盘是 Server Component，引入后整页降级为客户端渲染。手写零依赖、零客户端 JS、天然随主题色走 |
| 图表配色 | 以 ink 灰阶为主，强调蓝只用于悬停指向 | 遵循 globals.css 的既定约定——强调蓝全站只用在焦点环、导航选中态、主操作按钮。图表若铺满彩色，"可操作"这个语义就被稀释了 |
| 饼图 | 不做 | 无障碍差（色觉障碍用户无法区分扇区）。分布数据一律用横向条：名称、数值、长度并排，不依赖颜色也能读 |
| 数据来源 | 新增 `server/services/dashboard.ts` 聚合 | 规则要求组件不得直连 prisma；聚合逻辑集中在服务层，页面只做呈现 |
| 阅读量统计 | **不做排行图表** | 见第三节 |
| 单屏不滚 | 页面为一列 flex，页头与 KPI 行 `flex-none`，两行图表 `flex-1` 均分剩余高度 | 写死高度（如 `h-40`）会让不同视口下要么留白要么溢出。卡内超出的列表由卡片自身滚动消化，不顶出整页滚动条 |
| 依赖变更 | 无 | 不新增任何 npm 依赖 |

## 三、技术前提（已核实，非推测）

| 核实项 | 结论 | 影响 |
| --- | --- | --- |
| `Post.viewCount` 字段 | schema 中存在（`prisma/schema.prisma:72`），但**全仓库没有任何递增逻辑**，前台详情页也没有写入 | 该字段当前恒为 0。**本次不把它做成图表**——一个永远显示 0 的「阅读排行」比没有更糟。字段保留，等埋点补齐后再接入 |
| 可用的真实时间维度 | `createdAt`、`updatedAt`、`publishedAt`、`deletedAt`、`PostRevision.createdAt` | 趋势图基于这些字段，均为真实数据 |
| `cacheComponents: true` | 已开启（`next.config.ts:9`），后台 layout 已声明 `export const instant = false` | 仪表盘每个请求都读最新数据是正确的，不做缓存 |
| 后台布局 | 内容区是 `flex min-h-0 flex-1 flex-col`，页面自行用 `space-y-*` 控制间距 | 仪表盘按 `space-y-5` 组织，与其他后台页一致 |
| 时区 | 时间格式化必须放在服务端 | 客户端 `toLocaleString` 会因时区差异导致 hydration 不匹配（文章列表页已有同样的注释约定） |
| 图表包 | 当前 `package.json` 无任何图表相关依赖 | 与"不引入图表库"的决策互为印证 |

## 六、实施建议

- 图表不能是唯一的信息载体：数值一律以文字并排给出（分布条的「名称 + 数字」、柱状图的峰值与首尾日期），颜色与长度只作加速识别
- 定高布局的关键是 `min-h-0`：flex 子项默认按内容撑开，缺了它 `flex-1` 分不到高度，整页会重新出现滚动条
- 卡内内容超出时在**卡片内部**滚动（`ChartBody scroll`），不允许顶出整页滚动条
- 空数据必须有明确文案（如"近 30 天没有发布"），不能渲染一条平线误导用户
- 颜色只从 `--color-ink-*` / `--color-accent-*` / 语义色 token 取，不写字面色值

## 七、潜在风险

| 风险 | 影响 | 处置 |
| --- | --- | --- |
| 聚合查询变多拖慢首屏 | 仪表盘是进后台的第一页 | 全部查询用一次 `Promise.all` 并发；均为 count/groupBy，走已有索引。文章量级到万级前不构成问题 |
| 定高布局在小视口压扁图表 | 柱状图糊成一条 | `lg` 以下取消定高，退回按内容排布（窄屏本来就会滚，挤在一屏内每块都读不清）；柱区另有 `min-h-16` 兜底 |
| 卡内滚动条被误认为整页滚动 | 交互困惑 | 只有「分类分布」「待处理」「最近编辑」三处可滚，且卡片有明确边框界定范围 |
| `publishedAt` 为 null 的草稿 | 趋势图统计口径出错 | 趋势图只统计 `publishedAt` 非空的已发布文章 |
| 时间线查询窗口与趋势窗口不一致 | 趋势图静默丢数据 | 两者共用 `TREND_DAYS` 常量推导，不写第二个字面天数 |

## 十一、修订记录

### 2026-09-23：按用户反馈精简（初版实现后）

初版铺了 7 张卡 + 7 项快速入口，实际渲染后超出一屏、产生整页滚动条。用户要求去掉快速入口、内容构成、常用标签三块，并压缩空间。

**删除的 UI**

| 块 | 删除理由 |
| --- | --- |
| 快速入口（7 项宫格） | 侧栏导航已有分类 / 标签 / 回收站 / 日志入口，重复一遍只是占掉约 60px 高度 |
| 内容构成（占比条 + 页面·分类·标签计数） | 已发布 / 草稿两个数字在 KPI 行已有，占比条只是把同样的数换成百分比 |
| 常用标签（Top 8 分布） | 标签管理页本身就是带文章数的列表 |
| 迷你趋势线（Sparkline） | 与主趋势图信息重叠，且 KPI 卡改紧凑后没有它的位置 |

**随之回收的代码**（避免留下不被消费的查询与死组件）

- `components/charts.tsx`：删除 `Sparkline`、`SegmentedBar` 与 `Segment` 类型
- `server/services/dashboard.ts`：删除 `topTags`、`publishByWeek`、`counts.tags` / `categories` / `totalPosts` / `archivedPosts` / `revisions` / `trashedPosts` / `trashedPages`、`deltas.createdThisWeek` / `updatedThisWeek`
- 随之减少 5 条 SQL：标签计数（`listTagsWithCount`）、版本快照计数、本周新建、本周改动各一条，分类计数改为复用已有的分类查询

**空间优化手法**

1. 页面改为一列 flex：页头与 KPI 行 `flex-none`，两行卡片 `lg:flex-1` 均分剩余高度
2. `BarTrend` 由写死 `h-40` 改为柱区 `absolute` 铺在 `flex-1` 盒子里，跟随卡片高度伸缩
3. KPI 卡数字与单位改为同行基线对齐（原先单位独占一行，四张卡白吃约 18px）
4. 可能超出的列表（最近编辑、分类分布、待处理）改为**卡内滚动**，不顶出整页滚动条
5. 分类分布取 5 项（原 6 项）

**保留的 8 项数据**：已发布 / 草稿 / 页面 / 媒体文件（KPI）+ 30 天发布趋势 / 最近编辑 / 分类分布 / 待处理（卡片）
