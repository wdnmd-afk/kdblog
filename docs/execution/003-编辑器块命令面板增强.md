# 编辑器块命令面板增强（对齐语雀交互）

- 文档编号：003
- 状态：代码层已完成；typecheck / lint / build / 三个测试脚本全部通过，浏览器内的交互与视觉待人工确认（见第十三节）
- 创建日期：2026-09-21
- 适用范围：后台文章编辑器与独立页面编辑器的正文编辑能力
- 前置文档：002（斜杠命令、气泡菜单、工具栏的初版实现）

## 一、目标

把编辑器从「8 个斜杠命令 + 纯文本格式」扩到接近语雀的写作能力：

1. `#` 触发命令面板，`#1` / `#2` / `#3` 依次对应正文可用的三级标题
2. 斜杠命令触发条件从「空段落首字符」放宽到「行首或前一字符是空格」
3. 补齐已装扩展的缺失入口：表格、插入图片、文字对齐
4. 新增任务清单、代码块语言选择与语法高亮
5. 新增提示块 Callout 与折叠块 Details
6. 新增文字颜色、背景高亮、上下标

## 二、已确认的决策

| 决策项 | 结论 |
| --- | --- |
| `#1` 的含义 | 输出 `<h2>`，面板显示「一级标题」。正文仍不出 h1，SEO 结构不变，`sanitize` 不需要放开 h1 |
| `#` 可用的编号 | `#1`/`#2`/`#3` 三档；`#4` 起无匹配，面板不显示 |
| 触发条件 | 放宽到「行首 或 前一字符是空格」；列表项、引用块内允许；代码块内不允许 |
| 依赖策略 | 允许新增 MIT 许可的官方扩展（已核对全部为 MIT，非 Pro 私有包） |

## 三、技术前提（已实测核实，非推测）

实施前用临时脚本跑通了 `generateHTML` 的真实产物，以下结论直接决定改法：

| 核实项 | 实测结果 | 影响 |
| --- | --- | --- |
| lowlight 是否进 `generateHTML` | **不进**。服务端输出的仍是 `<pre><code class="language-javascript">`，无任何 `hljs-*` 节点 | 语法高亮是编辑器视图层的 ProseMirror 装饰器。**落库前必须补一道服务端高亮**，否则前台代码块没有着色 |
| `lowlight.highlight()` 返回类型 | hast 树（`{type:"element", tagName:"span", properties:{className:["hljs-keyword"]}}`），**不是 HTML 字符串** | 需自行序列化为字符串 |
| `lowlight.highlight()` 异常行为 | 语言未注册或为空串时**直接抛异常**（`Unknown language: ... is not registered`） | 落库链路必须 try/catch 兜底，否则一篇文章就能让保存接口 500 |
| lowlight `common` 注册语言数 | 37 种，含 `plaintext` | 语言选择器取这 37 项，`plaintext` 作为「纯文本」兜底 |
| Details 服务端产物 | `<details><summary>…</summary><div data-type="detailsContent">…</div></details>` | 白名单需登记 `details` / `summary` / `div[data-type]` |
| TaskList 服务端产物 | `<ul data-type="taskList"><li data-checked="true" data-type="taskItem"><label><input type="checkbox" checked="checked"><span></span></label><div>…</div></li></ul>` | 白名单需登记 `input`、`label` 与 `data-*` 属性 |
| 行内标记产物 | `<mark data-color="#fef08a" style="background-color: …">`、`<span style="color: …">`、`<sub>`、`<sup>` | 白名单需放开 `mark` / `sub` / `sup` 与 `span` 的 style |
| 中文字符在 generateHTML 输出中 | 被实体化为 `&#x6458;` 等 | 无害，`sanitize-html` 会还原，无需处理 |

## 五、操作步骤

### 第 1 步：触发条件放宽 + 双触发字符（`lib/tiptap/slash-command.ts`）

这是本次唯一的**既有逻辑改动**，其余都是新增，单独成步便于回归。

**1.1 放宽触发位置**

替换 `handleTextInput` 里的两处硬条件：

```ts
// 现在：必须是空段落 + 必须是这一段第一个字符
if (parent.type.name !== "paragraph") return false;
if ($from.parentOffset !== 0) return false;
```

改为：

```ts
// 代码块内的 "/" 是正文（注释、路径），不能弹面板
if ($from.parent.type.name === "codeBlock") return false;

// "/" 必须处于行首，或紧跟在空白之后。
// 这样 1/2、and/or、a/b 这类正文不会误触，而「…… 空格 + /」能唤出面板。
const charBefore = $from.parent.textBetween(
  Math.max(0, $from.parentOffset - 1),
  $from.parentOffset,
  undefined,
  "\0"
);
if ($from.parentOffset > 0 && !/\s/.test(charBefore)) return false;
```

要点：

- `textBetween` 的第 4 个参数用 `"\0"` 而非默认的空串——叶子节点（如图片）在默认配置下会被跳过，会让「图片后紧跟 `/`」误判为行首
- 不再限制 `parent.type.name === "paragraph"`：列表项、引用块、表格单元格里的段落都应支持，这正是语雀的行为。排除项只保留 `codeBlock`
- 插件 `apply` 里的守卫（`text.startsWith("/")`、`/[\s\n]/` 检测）保持不变，它负责在继续输入时收敛

**1.2 抽出统一的触发判断**

新增模块级函数，避免两个触发字符各写一遍：

```ts
/** 触发字符 */
const TRIGGERS = ["/", "#"] as const;
type Trigger = (typeof TRIGGERS)[number];

/**
 * 判断某个输入字符能否在当前位置唤出面板。
 *
 * 两个触发字符共用一套位置规则：行首，或前一字符是空白。
 */
function canTriggerAt(view: EditorView, from: number, char: string): boolean { … }
```

`handleTextInput` 改为 `if (!TRIGGERS.includes(text as Trigger)) return false;`，据此打开面板并记录 `trigger`。

**1.3 状态结构扩展**

`SlashMenuState` 增加一个字段（`query` 与 `range` 的语义完全复用，只多记一个触发来源）：

```ts
export interface SlashMenuState {
  /** 触发字符，决定过滤规则与面板标题 */
  trigger: Trigger;
  open: boolean;
  query: string;
  range: Range | null;
  selected: number;
  from: number;
}
```

`apply` 中的守卫要把 `text.startsWith("/")` 改为 `text.startsWith(prev.trigger)`。

**1.4 `#` 的查询规则**

`#` 后只接受数字，且走**独立过滤**而非 `filterItems`：

```ts
/**
 * "#" 的查询只认数字，且数字直接对应标题层级。
 *
 * 不走 filterItems 的标题/关键词匹配：用户输入 "#1" 时期待的是
 * 「第一个标题」，而不是「标题里含 1 的命令」。若按标题匹配，
 * "一级标题" 里含 "一" 不含 "1"，列表会瞬间清空。
 */
const HASH_HEADING_LEVELS: Record<string, 2 | 3 | 4> = {
  "1": 2, // 正文最大可用层级
  "2": 3,
  "3": 4,
};

export function filterItemsByTrigger(items, state): SlashMenuItem[] { … }
```

规则：

- `query` 为空 → 显示全部 3 个标题项（面板上给出 `#1`/`#2`/`#3` 提示，用户不必先记住数字）
- `query` 是 `1`/`2`/`3` → 只显示对应一项
- 其它任何字符 → 空列表，`SlashMenu` 返回 `null`（面板自动消失，不需要额外关闭逻辑）
- 已有守卫保证 `query` 里不会出现空格或换行，因此 `#` 后打中文会立刻收敛

### 第 2 步：命令项的层级与分组（`lib/tiptap/slash-command.ts`）

命令项从 8 个扩到 20 个左右，平铺会变得难找，因此加分组：

```ts
export interface SlashMenuItem {
  run: (props: { editor: Editor; range: Range }) => void;
  title: string;
  description: string;
  keywords: string[];
  icon: string;
  /** 分组名。同组连排，组间画分隔线——平铺二十项时找不到东西 */
  group: "基础" | "列表" | "插入" | "样式";
  /** 仅在某个触发字符下出现。省略表示两者都出现 */
  onlyFor?: Trigger;
  /** 标题右侧的操作提示，如 "#1" */
  shortcut?: string;
}
```

命令清单：

| 分组 | 命令 | 图标 | 备注 |
| --- | --- | --- | --- |
| 基础 | 一级标题 / 二级标题 / 三级标题 | heading2/3/4 | 输出 h2/h3/h4；`shortcut` 标 `#1`/`#2`/`#3`；`keywords` 补 `#1` `#2` `#3` |
| 基础 | 正文 | type | 新增，`setParagraph()`。把标题改回正文是最常用的反向操作 |
| 列表 | 无序列表 / 有序列表 / 任务清单 | list / listOrdered / listTodo | 任务清单为新增 |
| 插入 | 表格 / 图片 / 分割线 | table / image / minus | 表格与图片为新增入口 |
| 样式 | 引用 / 代码块 / 提示块 / 折叠块 | quote / squareCode / info / chevronDown | 后两个为新增 |

要点：

- 标题项的 `run` 需在 `deleteRange` 之后先 `setParagraph()` 再 `toggleHeading()`——否则在已有标题上执行 `#2` 时，`toggleHeading` 会因为已是标题而**关掉**标题，行为与预期相反
- 图片项只能出现在斜杠面板：它需要打开文件选择框，`run` 接收不到 DOM 上下文，因此 `run` 改为调用一个由 UI 层注入的回调。具体做法：`SlashMenuItem` 增加可选的 `kind: "command" | "action"`，`action` 类型由 `SlashMenu` 组件直接处理而不用 `run`

### 第 3 步：扩展注册（`lib/tiptap/extensions.ts`）

`sharedExtensions` 是前后端共用的同一份列表，新增节点必须加在这里（只加客户端会导致服务端 `generateHTML` 报 `Unknown node type`）。

```ts
StarterKit.configure({
  heading: { levels: [2, 3, 4] }, // 不变
  link: false,                     // 不变
  // 关闭 StarterKit 自带的 codeBlock，改由低亮版本提供。
  // 两者同名，同时启用会报 Duplicate extension names
  codeBlock: false,
}),
CodeBlockLowlight.configure({ lowlight }),
Details.configure({ persist: false, HTMLAttributes: { class: "kd-details" } }),
DetailsSummary,
DetailsContent,
TaskList,
TaskItem.configure({ nested: true }),
Highlight.configure({ multicolor: true }),
// 只取颜色三项，不要 fontFamily / fontSize / lineHeight：
// 那三项会引入任意字体与字号，是本设计系统刻意不收的口子
TextStyleKit.configure({ fontFamily: false, fontSize: false, lineHeight: false }),
Subscript,
Superscript,
Callout, // 自研，见第 6 步
```

新增 `lib/tiptap/lowlight.ts` 导出单例，避免前后端各建一份：

```ts
import { createLowlight, common } from "lowlight";
export const lowlight = createLowlight(common);
```

> `lowlight` 会连带把 `highlight.js` 拉进依赖图。它同时出现在客户端（编辑器装饰）与服务端（落库高亮），两份都是必需，不做拆分。

### 第 4 步：服务端语法高亮（关键，容易漏）

`generateHTML` 不含高亮（见第三节实测），因此 `lib/tiptap/sanitize.ts` 的 `renderContentHtml` 需要在 sanitize 之后补一道后处理：

```ts
/**
 * 给代码块补语法高亮。
 *
 * lowlight 在编辑器里靠 ProseMirror 装饰器着色，装饰器不会进入
 * generateHTML 的输出——不补这一步，前台代码块就是一片纯黑文字。
 *
 * 用正则替换而非解析 HTML：此处输入的 HTML 全部由 generateHTML 生成，
 * 结构可预期，`<pre><code class="language-x">…</code></pre>` 是固定形态。
 */
function highlightCodeBlocks(html: string): string { … }
```

实现要点：

- 逐个匹配 `<pre><code class="language-([\w-]+)">([\s\S]*?)</code></pre>`
- 取出的代码文本需先**反转义**（`generateHTML` 会输出 `&lt;` `&gt;` `&amp;`），再交给 `lowlight.highlight()`
- 语言不在 `lowlight.listLanguages()` 内时**跳过**（返回原文），绝不抛异常——这是落库链路上的代码，一篇文章不能拖垮保存接口
- 高亮结果是 hast 树，需要一个小序列化器（约 20 行）：文本节点转义、`element` 转 `<span class="hljs-x">`
- 无 `language-` class 的代码块（用户没选语言）直接跳过

### 第 5 步：白名单同步（`lib/tiptap/sanitize.ts`）

> ⚠ 这是本次最容易出事的一处：漏登记会让新节点在**发布后静默消失**，编辑器里却一切正常，排查成本极高。

**新增标签**

```
mark  sub  sup  details  summary  label  input  div
```

（`div` 只用于 `detailsContent` 与 `taskItem` 的内层容器，通过下面的属性白名单限制形态。）

**新增属性**

```ts
details: ["open"],
summary: ["data-type"],
div: ["data-type"],
input: ["type", "checked", "disabled"],
mark: ["data-color"],
span: ["style"],          // textStyle 的颜色输出
ul: ["data-type"],
li: ["data-type", "data-checked"],
```

**styles 白名单必须细化**（当前是 `"*": { "text-align": [...] }`，直接给 `span` 放开 `color` 等于开了任意 CSS 注入的口子）：

```ts
allowedStyles: {
  "*": { "text-align": [/^(left|right|center|justify)$/] },
  // 只认十六进制与 rgb/hsl 函数式写法，杜绝 expression()、
  // url()、var() 等可用于注入的取值
  span: {
    color: [/^#[0-9a-fA-F]{3,8}$/, /^rgba?\([\d\s.,%]+\)$/],
    "background-color": [/^#[0-9a-fA-F]{3,8}$/, /^rgba?\([\d\s.,%]+\)$/],
  },
},
```

**已确认但当前未放开的既有隐患**

`a` 的 `target` 目前在 `allowedAttributes.a` 里，但不在 `allowedTags` 之外的 `allowedSchemes`；`transformTags` 已强制 `rel`/`target`，无需改动。

### 第 6 步：Callout 自研节点（`lib/tiptap/callout.ts`）

Tiptap 官方无对应扩展，需要自写。控制在最小可用范围：

```ts
export type CalloutTone = "info" | "warning" | "success" | "danger";

export const Callout = Node.create({
  name: "callout",
  group: "block",
  // 不允许嵌套 callout：样式上无法表达两层缩进，且没有实际需求
  content: "paragraph+",
  defining: true,   // 内部编辑不影响兄弟节点
  addAttributes: () => ({
    tone: {
      default: "info",
      parseHTML: (el) => el.getAttribute("data-tone") ?? "info",
      renderHTML: (attrs) => ({ "data-tone": attrs.tone }),
    },
  }),
  parseHTML: () => [{ tag: "div[data-type='callout']" }],
  renderHTML: ({ HTMLAttributes }) => [
    "div",
    mergeAttributes(HTMLAttributes, { "data-type": "callout", class: "kd-callout" }),
    0,
  ],
  addCommands: () => ({ setCallout, toggleCallout, unsetCallout }),
});
```

四个 tone 的元数据（图标色、底色、默认文案）单独放 `lib/tiptap/callout-tone.ts`，供编辑器与样式层共用同一份定义，避免「编辑器里是黄底、前台变成灰底」。

配套 CSS 加在 `app/globals.css` 的 `.prose-article` 之外，**同时匹配 `.tiptap`（编辑区）与 `.prose-article`（前台）**，因为两处的容器 class 不同。

## 六、实施建议

1. **按步骤顺序做，第 1 步单独验证后再动其余**。它是唯一的既有行为改动，出问题会直接影响现在能用的斜杠命令。
2. **每一步之后跑一次探查脚本**（临时 `scripts/probe-*.ts`，约 30 行，用完即删）验证 `generateHTML + sanitize` 的产物。本次第三节的全部结论都来自这种脚本，比读类型定义可靠得多，成本只有几十秒。
3. **先改 `sanitize` 再写节点**。反过来做的话，编辑器里一切正常、发布后内容消失，会误判为节点实现有 bug。
4. **`deleteRange` 之后再改块类型**。命令的 `range` 包含用户输入的 `/xxx` 或 `#1`，若先改块类型再删除，删除范围在类型变更后可能失效。
5. **色板与正则同源**：把允许的颜色常量提到一个共享模块，`sanitize` 的白名单从它派生，避免两处各写一份后悄悄分叉。

## 七、风险分析

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| `sanitize` 白名单漏登记 | 新节点发布后静默消失，编辑器内正常 | 每个节点都跑探查脚本核对 sanitize 后的产物，不靠推断 |
| 服务端高亮遇到异常语言 | 保存/发布接口 500，文章丢失 | `highlightCodeBlocks` 整体 try/catch，任何异常都返回原 HTML |
| style 白名单放开颜色 | 任意 CSS 注入 | 白名单细化到 `span` 两种属性，取值用严格正则限定；色板只输出十六进制 |
| 触发条件放宽后误触 | 正文里的 `a / b` 之类唤出面板 | 只认「行首或前接空白」；已有的「出现空格即收敛」守卫继续生效 |
| `#` 与用户的正文习惯冲突 | 章节目号（如 `#1 引言`）会瞬间弹面板 | `#` 后接非数字时面板立刻消失；`#1` 后接空格也会因既有守卫收敛。极端情况下按 Esc 会连 `#1` 一起删掉——这是可接受的，因为 `#` 在第 1 步之前也不会出现在正文开头 |
| TaskItem 的 checkbox 与全局 checkbox 样式冲突 | 勾号重复、尺寸错位 | 第 8 步显式覆盖 `ul[data-type="taskList"]` 下的 checkbox |
| 工具栏按钮增至 18 个 | 窄屏换行、编辑器高度被挤 | 分组重排并在窄屏下确认；必要时收起低频项（表格、折叠块）到「更多」下拉 |
| 面板显示「一级标题」而工具栏显示「二级标题」 | 用户困惑 | 面板的标题项在 `description` 中写明实际层级（如「章节标题 · H2」），不改工具栏文案以保持 002 的既有表述 |
| `highlight.js` 体积 | 客户端与服务端包同时增大 | 不做语言按需加载（`common` 仅 37 种，体积可接受）；若后续构建体积告警，再改为按 `plaintext` 兜底的动态注册 |
| 编辑器与前台两套容器 class | 样式只写一处导致另一处失效 | 所有新增选择器同时挂 `.tiptap` 与 `.prose-article` |
| `#` 面板在新版本文档上更复杂 | 状态机出错会让两个触发字符互相干扰 | 两者共用同一套 `range` / `query` / `selected`，只多存一个 `trigger` 字段，不引入第二套状态 |

## 八、优化方案（本期不做）

1. **代码块语言按需加载**：`common` 换成显式注册常用 10 种，减小客户端体积
2. **表格行列操作 UI**：选中单元格后浮出「插入行/列、删除行/列、合并」
3. **Callout 图标自定义**：当前用伪元素，后续可换成可选的 icon 属性
4. **命令面板最近使用排序**：记录使用频次，高频命令上浮

## 十二、实施中的偏离

| 原计划 | 实际做法 | 原因 |
| --- | --- | --- |
| Callout 用 NodeView 渲染语气切换按钮 | 不做 NodeView，语气切换放进气泡菜单 | NodeView 要把一个 `"use client"` 组件挂进 `sharedExtensions` 的依赖链（那份列表服务端 `generateHTML` 也要加载），只能靠动态 `import` 绕开。代价远大于收益，而气泡菜单天然知道光标是否在提示块内 |
| 用 `entities` 包做反转义 | 自写 10 行 `unescapeHtml` | `entities` 不是本项目的直接依赖，只是 `happy-dom` 的传递依赖。pnpm 的严格 `node_modules` 下从 `lib/` 直接 import 有解析失败风险。真正需要处理的只有 `generateHTML` 会产出的那几种实体 |
| `SlashMenu` 接收 `onPickImage` 回调 | 组件自带隐藏的 file input，`onPickImage` 整个移除 | 跨组件传一个「去点另一个组件的 input」的回调只是绕路。需要共用的上传逻辑已经在 `lib/upload-image.ts` 里了，文件框各留一份无害 |
| 工具栏扩充后把低频项收进「更多」下拉 | 直接平铺，从 13 个增至 16 个 | 「更多」下拉属于额外改动，用户未确认，不做 |
| 文字对齐放进气泡菜单 | 放进工具栏，作为独立分组 | 对齐是块级属性，气泡菜单的触发条件是「选中非空文本」，与块级语义不符；放工具栏也更符合「块级走工具栏」的既有分工 |
| 代码块语言选择放在气泡菜单内 | 放进工具栏，光标在代码块内时才出现 | 显示条件是「光标在代码块内」，与气泡菜单「选中非空文本」的条件互斥，混在一起会让 `shouldShow` 变成一堆或条件 |
| 计划里的 `filterItems` 复用给 `#` | 新增 `filterItemsByTrigger` 分派 | `#1` 若走关键词匹配，「一级标题」里含「一」不含「1」，列表会瞬间清空。数字必须直映射层级 |
