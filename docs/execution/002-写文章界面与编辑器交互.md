# 写文章界面重构与编辑器交互增强

- 文档编号：002
- 状态：代码层已完成；typecheck / lint 通过，功能验证待数据库就绪
- 创建日期：2026-09-18
- 适用范围：后台文章编辑页（写文章）的界面重构、编辑器交互补全、公共反馈组件扩充
- 参考实现：halo `ui/console-src/modules/contents/posts/PostEditor.vue`、`ui/packages/editor/`

## 一、目标

把文章编辑页从"表单堆叠"改造为"写作优先"的独立界面：

1. 写文章页只保留标题与正文，SEQ/分类/标签等设置移入右侧抽屉
2. 编辑器补上现代写作所需的三项交互：斜杠命令、选中浮动菜单、图片粘贴与拖入
3. 正文具备本地草稿保护（localStorage）与 Ctrl+S 保存
4. 补齐公共组件：Modal、Drawer、DropdownMenu、Tooltip

## 二、范围

### 明确不做（用户已确认排除）

| 项 | 说明 |
| --- | --- |
| 评论功能 | 需求排除 |
| 定时发布 | 需求排除，`ContentStatus.SCHEDULED` 继续保留但不实现调度器 |
| 块拖拽手柄 | 用户未选，实现成本高、收益低于斜杠命令 |
| 封面图字段 | 需要数据库迁移，不在本期 |
| 置顶 / 可见性 / 允许评论 | halo 有，kdblog 定位不需要 |

### 不做但需记录的技术约束

| 约束 | 原因 |
| --- | --- |
| 不安装 `@tiptap/suggestion` | 斜杠命令自行实现，避免新增依赖。`@tiptap/react` 3.31.3 已内置 BubbleMenu，无需额外包 |
| 新增编辑器扩展只能进 `editorOnlyExtensions` | `sharedExtensions` 与服务端 `generateHTML` 共用，加入客户端专用扩展会导致服务端渲染报错 |
| `saveDraft` 会重写 `contentHtml` | 对已发布文章执行会直接改变前台内容。因此自动保存只写 localStorage，不静默落库 |

## 四、操作步骤

### 第 1 步：公共组件层

**新增 `components/overlay.tsx`（`"use client"`）**

| 组件 | 说明 |
| --- | --- |
| `Drawer` | 右侧滑出面板。`fixed inset-y-0 right-0`，遮罩点击关闭，Esc 关闭，打开时锁定 body 滚动 |
| `Modal` | 居中模态。与 `feedback.tsx` 的 ConfirmDialog 共用遮罩与键盘行为 |
| `DropdownMenu` | 触发器 + 弹出菜单，支持点击外部关闭 |
| `Tooltip` | 纯 CSS 悬浮提示，用于工具栏按钮 |

约束：`components/ui.tsx` 是服务端可用的纯展示组件，不得混入 `"use client"`。交互组件单独成文件。

**`components/feedback.tsx` 保持不变**（已有 toast + confirm 已满足需求）。

### 第 2 步：编辑器扩展

**新增 `lib/tiptap/slash-command.ts`**

自行实现的斜杠命令扩展，不依赖 `@tiptap/suggestion`：

- 触发条件：光标位于空段落（或段落开头）且输入 `/`
- 用 ProseMirror 的 `Plugin` 监听 `handleTextInput` 与 `handleKeyDown`
- 状态通过 `pluginKey` 暴露给 React 层（命令列表、选中索引、锚点坐标）
- 键盘：`↑↓` 移动、`Enter` 选中、`Esc` 关闭
- 中文输入法兼容：`compositionstart/end` 期间不触发

命令项：二级/三级/四级标题、无序/有序列表、引用、代码块、分割线、图片。

**`lib/tiptap/extensions.ts` 增加 `editorOnlyExtensions`**

- `SlashCommand`（上一步）
- 保持 `sharedExtensions` 不变

> `sanitize.ts` 白名单无需改动：斜杠命令只产生已有节点类型。

### 第 3 步：编辑器组件

**新增 `components/editor/bubble-menu.tsx`**

用 `@tiptap/react` 内置的 `BubbleMenu`：

- 选中非空文本时浮出
- 按钮：加粗、斜体、下划线、删除线、行内代码、链接、清除格式
- 链接走行内输入而非 `window.prompt`（当前实现的 `window.prompt` 体验差且无法校验）

**新增 `components/editor/slash-menu.tsx`**

斜杠命令的 UI 层，接收扩展暴露的状态，渲染过滤后的命令列表，定位到光标处。

**新增 `components/editor/editor-content.tsx`**

封装 `EditorContent` 并挂载：
- `handlePaste`：剪贴板含图片文件时走 `/api/upload` 上传后插入
- `handleDrop`：拖入图片文件同上
- 两者共用一个 `uploadAndInsert` 函数，失败时通过 `useFeedback().toast` 报错

**保留并重构 `app/(admin)/admin/posts/[id]/PostEditor.tsx` 的 `EditorToolbar`**

工具栏保留（斜杠命令不能替代显式工具栏），但：
- 用新的 `Tooltip` 替代原生 `title`
- 从 `PostEditor.tsx` 抽出到 `components/editor/toolbar.tsx`

### 第 4 步：本地草稿

**新增 `lib/use-local-draft.ts`（`"use client"`）**

- key：`kdblog:post-draft:{id | "new"}`
- 写入时机：正文或标题变化后 debounce 800ms
- 存储内容：`{ title, contentJson, savedAt }`
- 提供 `{ draft, clear, saveNow }`
- 页面加载时若本地草稿比服务端内容新，弹出确认让用户选择恢复或丢弃
- 发布/保存成功后清除本地草稿

**Ctrl+S**：在 `PostEditor` 内监听 `keydown`，`(e.ctrlKey || e.metaKey) && e.key === "s"` 时 `preventDefault()` 并触发保存草稿。

### 第 5 步：页面重构

**`app/(admin)/admin/posts/[id]/layout.tsx`（新增）**

后台壳内嵌套的编辑器专用壳：去掉页面内边距与页脚，让编辑区占满可用高度。放在这个目录下不影响 `pages/[id]`。

**`app/(admin)/admin/posts/[id]/page.tsx` 重构**

- 移除 `<h1>新建文章/编辑文章</h1>` 与 `mb-6`
- 数据加载保持不变

**`PostEditor.tsx` 重构后的结构**

```
<div 全高 flex-col>
  <EditorTopBar>      ← 返回 | 状态徽标 | 预览 | 设置 | 保存草稿 | 发布
  <TitleInput>        ← 无边框大标题输入
  <EditorArea>        ← 工具栏 + 正文，flex-1 可滚动
  <SettingsDrawer>    ← 右侧抽屉，分三组
</div>
```

**抽屉分组**

| 分组 | 字段 |
| --- | --- |
| 基础 | slug（带「由标题生成」按钮）、分类、标签、摘要 |
| SEO | SEO 标题、SEO 描述、关键词、Canonical、og 图片、robots |
| 版本 | 版本快照列表与回滚（原「版本」Tab 内容） |

SEO 字段的填写规范说明与字数进度条（`Meter`）保留，随字段一同移入抽屉。

**保留的行为**

- 新建时按标题自动生成 slug，已有 slug 不覆盖
- SEO 校验失败时自动打开抽屉并滚到 SEO 分组（替代原先切 Tab 的逻辑）
- 预览：先落草稿再签发链接
- 版本回滚的二次确认

## 五、实施建议

1. **按步骤顺序做，每步可独立验证**。第 1、2 步是纯新增，不影响现有功能；第 5 步改动最大，放最后。
2. **斜杠菜单的定位用 `editor.view.coordsAtPos`**，不要用鼠标坐标——键盘触发时没有鼠标位置。
3. **图片上传复用 `/api/upload`**，与工具栏按钮走同一接口，避免两套上传逻辑。
4. **抽屉用 `fixed` 定位**，而不是挤压编辑区宽度：写作时打开设置不应导致正文重排。
5. **本地草稿的过期**：只保留最近一份，不做历史。恢复提示要写清时间戳。

## 六、风险分析

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 斜杠命令与中文输入法冲突 | 输入 `/` 后的中文候选被命令菜单拦截 | 监听 `compositionstart/end`，组合期间不触发；命令列表只在输入 `/` 后紧跟非空格字符时出现 |
| 自行实现斜杠命令缺少边界处理 | 长文档、跨段落、撤销栈异常 | 插件只在顶层段落生效；命令执行走 `editor.chain().focus()`，与工具栏同一路径 |
| localStorage 草稿与服务端内容冲突 | 用户误恢复旧内容覆盖新改动 | 明确展示两份内容的保存时间；默认不自动恢复，需用户点确认 |
| 抽屉内表单状态与编辑器状态不同步 | 保存时丢失抽屉里的改动 | 抽屉字段与编辑器共用同一个 `useState` 集合，抽屉只是渲染层，不持有独立状态 |
| 页面重构导致原有 SEO 校验提示失效 | 用户发布失败后找不到错误位置 | 保留 `fieldErrors` 展示，并在校验失败时自动开抽屉、滚到对应分组 |
| `PostEditor` 被页面编辑器复用 | 改动波及 `pages/[id]` | 已确认 `PostEditor` 仅被 `posts/[id]/page.tsx` 引用，`PageEditor` 是独立文件 |

## 八、验证方式

代码层：

1. `pnpm typecheck` —— 新增组件与钩子的类型完整性
2. `pnpm lint` —— 无未使用导入、无 hook 依赖告警
3. `pnpm build` —— 确认 `editorOnlyExtensions` 的新增没有污染服务端渲染

功能层（需数据库就绪后手工验证）：

| 场景 | 预期 |
| --- | --- |
| 新建文章，标题留空 | 保存时校验提示，不落库 |
| 输入标题 | slug 自动生成；已保存文章的 slug 不被覆盖 |
| 正文输入 `/` | 命令菜单出现；`↑↓` 与 `Enter` 可用；`Esc` 关闭 |
| 选中文字 | 浮动菜单出现，加粗/链接可用 |
| 截图后 Ctrl+V | 图片上传并插入正文 |
| 拖入图片文件 | 同上 |
| 写一半关闭标签页后重开 | 提示恢复本地草稿，含保存时间 |

| 发布但 SEO 不完整 | 抽屉自动打开并滚到 SEO 分组，字段级错误可见 |
| 编辑已发布文章并保存草稿 | 前台内容随之更新（现有行为，需在测试中确认符合预期） |
| 打开设置抽屉 | 编辑区不重排 |
| 版本回滚 | 二次确认后内容恢复到编辑器 |

## 十、实施中的偏离

| 原计划 | 实际做法 | 原因 |
| --- | --- | --- |
| 新建 `posts/[id]/layout.tsx` 做编辑器专用壳 | 未新建。编辑器用负外边距抵消后台壳内边距，并给壳的内容容器加 `min-h-0` | 壳的内边距被其余所有管理页依赖，为编辑器一处改动要连带调整那些页面。让特例只出现在特例处，改动面更小 |
| 斜杠命令用 `@tiptap/suggestion` | 自行实现约 200 行的 ProseMirror 插件 | 未新增依赖。suggestion 面向「任意字符触发的提及」场景，这里只需要「空段落打 / 弹固定列表」，用不上它的装饰与异步查询能力 |
| 未提及 | 新增 `lib/upload-image.ts` | 工具栏、粘贴、拖入三处打同一个上传接口，各写一遍迟早分叉 |
| 未提及 | 修改 `server/actions/post.ts` | 回滚后编辑器内容不会更新：`useEditor` 的 content 只在挂载时读一次，`router.refresh()` 改不动已存在的 Tiptap 实例。让 action 把恢复后的内容交回来 |
| 未提及 | 补 `globals.css` 的占位符样式 | `Placeholder` 扩展一直在用，但配套 CSS 从未写过——占位提示此前实际从未显示，且不报错 |
