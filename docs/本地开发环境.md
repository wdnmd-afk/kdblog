# 本地开发环境

本文件记录本机（Windows 11 build 26200）实际可用的环境配置，以及搭建时踩到的问题。

## PostgreSQL

**版本：16.6**，非标准位置安装（未注册为系统服务，不写注册表）。

| 项 | 路径 |
| --- | --- |
| 二进制 | `E:\pg16\pgsql\bin` |
| 数据目录 | `E:\pg16data` |
| 端口 | 5432 |
| 超级用户 | `postgres`（trust 认证，无密码） |
| 业务库 | `kdblog` |
| 日志 | `E:\pg16data\server.log` |

### 启停命令

```bash
# 启动
"E:/pg16/pgsql/bin/pg_ctl" -D "E:/pg16data" -l "E:/pg16data/server.log" start

# 停止
"E:/pg16/pgsql/bin/pg_ctl" -D "E:/pg16data" stop

# 状态
"E:/pg16/pgsql/bin/pg_ctl" -D "E:/pg16data" status

# 连接
"E:/pg16/pgsql/bin/psql" -U postgres -h 127.0.0.1 -p 5432 -d kdblog
```

数据库**不会随开机自启**。每次重启机器后需手动执行上面的 start 命令，否则 `pnpm dev` 会报 `ECONNREFUSED`。

### 为什么不是 18.x

最初通过 scoop 安装了 PostgreSQL 18.1，但 `initdb` 在 `performing post-bootstrap initialization` 阶段稳定崩溃：

```
child process was terminated by exception 0xC0000005
```

排除过的因素：VC++ 运行库齐全（`vcruntime140.dll` 等均在）、scoop 的 `data` 目录 junction 链接（换独立目录仍崩）。同一步骤连续崩溃三次后改用 16.6，一次成功。

因此：**本机不要用 PostgreSQL 18.x**。若将来需要升级，先在独立目录验证 `initdb` 能否走完。

### 认证配置说明

`initdb` 时指定了 `--auth=trust`，即本机连接免密码。这仅适用于开发环境，生产环境必须改为 `scram-sha-256` 并设置密码。

## 环境变量

`.env` 已配置好并可直接使用（该文件在 `.gitignore` 中，不会提交）：

```
DATABASE_URL="postgresql://postgres@127.0.0.1:5432/kdblog?schema=public"
```

`AUTH_SECRET` 与 `PREVIEW_SECRET` 目前是开发用占位值，**上生产前必须替换**：

```bash
openssl rand -base64 32
```

## 初始管理员

由 `pnpm db:seed` 创建，凭据取自 `.env` 的 `SEED_ADMIN_*`：

- 账号：`admin`
- 密码：`123456`

登录地址 `http://localhost:3000/login`。密码经 argon2 哈希存储，重复执行 seed 会覆盖密码（可用于忘记密码时重置）。

### 账号字段不是邮箱

`User.email` 列名保留了 `email`，但登录校验已放宽为「任意非空字符串」，因此可以用 `admin`
这类简短用户名。改动位置：

- `lib/auth.ts` 的 `credentialsSchema` 去掉了 `.email()` 约束
- `app/login/page.tsx` 的输入框改为 `type="text"`（`type="email"` 会被浏览器内置校验拦掉）

若将来要恢复邮箱登录，把这两处改回去即可，数据库无需迁移。

### 密码强度

`123456` 是弱密码，仅用于本地开发。`prisma/seed.ts` 会在密码为纯数字或短于 12 位时打印告警，
但不阻断执行。**部署前必须改强密码并重新执行 seed**。

## 常用命令

```bash
pnpm dev          # 开发服务器（需先启动 PostgreSQL）
pnpm build        # 生产构建（不需要数据库连接）
pnpm typecheck    # 类型检查
pnpm lint         # ESLint
pnpm db:migrate   # 创建并应用迁移
pnpm db:seed      # 写入种子数据
pnpm db:studio    # Prisma Studio 可视化查看数据
```

## 冒烟测试

`scripts/smoke-test.ts` 直接调服务层验证发布主链路，绕过浏览器登录：

```bash
pnpm tsx scripts/smoke-test.ts
```

覆盖：发布事务、SEO 强校验、`contentHtml` 预渲染与 sanitize（含下划线白名单）、版本快照、标签自动创建、软删除隔离。

**注意**：该脚本会写入真实数据（一篇标题为「冒烟测试：验证发布链路」的文章及两个标签），仅供本地使用。清理：

```sql
DELETE FROM posts WHERE slug = 'smoke-test-publish';
```

由于脚本绕过 action 层，不会触发 `updateTag`，因此前台缓存与 sitemap 不会立即反映这篇文章——这是预期行为，正好验证了缓存按 tag 失效的机制在生效。
